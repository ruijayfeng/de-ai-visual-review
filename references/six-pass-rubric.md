## 通用测试

### 3 秒测试

只看 3 秒，然后回答：这一屏在说什么？下一步该看哪里/做什么？

答不出来，通常不是“不够精致”，而是焦点或文案失败。先修 Pass 1/5，不要先加动效。

### 眯眼测试

眯到看不清字，只剩块面。此时应该仍能看出：标题、正文组、主操作、次要信息。如果所有块面一样重，或者满屏碎块，先处理层级和容器。

### 删除测试

每删一个元素，问：删掉后信息或操作是否受损？

- 不受损：它大概率是装饰，删。
- 受损但可以换位置/换形式：降级，不一定要保留原样。
- 受损且无法替代：保留，并给它明确层级。

### 静音测试

把动画静音、甚至遮住动效看静态帧。信息仍应完整；动效只负责引导、变化或情绪，不应是唯一的信息载体。

### 最终尺寸测试

在用户真正观看的尺寸看，不是在设计稿 200% 缩放看：

- 手机：390×844 左右。
- 桌面：1440×900 左右。
- 横屏视频：1920×1080。
- 竖屏视频：1080×1920。

字号、线宽、图标和动效幅度都按这个尺寸判断。

## Pass 0：锁定画面

先写三行，不要跳过：

```text
观众：______
观看尺寸：______
这一屏/这一镜只让人看懂：______
```

再列“不能动”的清单：事实、数字、法律文字、表单 label、导航、按钮文案、alt/ARIA 名称、品牌资产。

如果用户没有给观看尺寸，按最可能的场景推断并说明。比如“按 1440 桌面审查；手机端只做了静态检查”。

## Pass 1：文案

### 常见 AI 味信号

- 标题上方一行全大写英文小字，但没有分类、来源或导航作用。
- 大标题说“让协作更简单”，下面小字又说“更简单的协作方式”。
- 每个区块都有一句“解释这个区块在讲什么”的元文案。
- 同一页出现三个“开始使用”，而且都是主按钮。
- 数字前后加“实时”“智能”“一站式”等没有证据的形容词。
- 为了显得完整，把一句人话拆成“标题 + 副标题 + 描述 + 标签”四层。

### 判断规则

保留：

- 导航、面包屑、步骤编号、字段 label、单位、日期、来源。
- 法律、安全、价格、限制条件、错误提示。
- 真正提供分类的 kicker，例如“案例研究 / 2026”。
- 品牌语气中不可替代的一句短句。

删除或合并：

- 复述标题的副标题。
- 不承载信息的装饰英文。
- 解释设计意图的文案（“下面我们来看……”）。
- 与主 CTA 竞争的第二、第三个主按钮。
- 没有证据支撑的形容词堆叠。

### 修复手法

1. 先删，不急着改写。
2. 能合并进标题就合并。
3. 需要保留但不应抢眼，降为 caption、脚注、tooltip 或折叠区。
4. 用间距和分组代替“小标题 + 说明”的层层解释。

### 例子

Bad：

```text
AI-POWERED COLLABORATION
让团队协作更高效
让团队以前所未有的方式高效协作
[开始使用] [了解更多] [预约演示]
```

Better：

```text
让团队协作更高效
把讨论、文件与决策放在同一个工作区。
[开始使用]
```

“了解更多”如果确实有内容，降为文字链接；“预约演示”放到次要位置。不要为了对称硬留三个按钮。

### 扫描器对应

`copy.eyebrow`、`copy.repeated-heading`、`copy.generic-phrase`、`copy.placeholder`。扫描器只能抓模式，最终要回到画面判断。

## Pass 2：容器

### 常见 AI 味信号

- 每个数字、图标、段落都套一张卡。
- 卡片里再套卡片，或者卡片上再加彩色左边框。
- 所有卡片都是同样的圆角、阴影、渐变边，像组件库默认值。
- 静态标签也做成胶囊按钮，暗示可点击但其实不可点。
- 用玻璃拟态和发光代替层级。
- 分割线、边框、背景、阴影同时出现，表达同一件事。

### 判断规则

保留边界，当它承担以下至少一个职责：

- 分组：这些内容属于同一件事。
- 层级：浮层、弹窗、菜单确实在页面之上。
- 交互：按钮、输入框、可点击卡片需要可感知的 hit area。
- 状态：选中、错误、禁用、拖拽目标需要明确反馈。

删除边界，当它只是：

- 让空白看起来不那么空。
- 给每个区块同样的“完成度”。
- 模仿某个模板的卡片网格。
- 用阴影制造并不存在的层级。

### 修复手法

1. 先删背景、阴影、彩边，只留内容。
2. 需要分组时，先用间距；不够再用一条 1px 分割线。
3. 需要点击时，保留一个清楚的边界和 hover/focus 反馈，不要三层套框。
4. 数字列表优先用对齐的行、定义列表或表格，不必每人一张卡。
5. 圆角只保留一套尺度；不要 8px、12px、16px、24px 混用。

### 例子

Bad：

```html
<div class="card glow">
  <div class="card-inner">
    <span class="pill">01</span>
    <h3>更快</h3>
    <p>更快的体验</p>
  </div>
</div>
```

Better：

```html
<div class="stat-row">
  <span class="stat-index">01</span>
  <div>
    <h3>更快</h3>
    <p>首屏加载从 2.4s 降到 0.9s。</p>
  </div>
</div>
```

### 扫描器对应

`container.card-chrome`、`container.glass`、`color.gradient-overload`。数量多不等于一定错；如果页面是价格表或可点击图库，卡片边界可能是合理的。

## Pass 3：颜色

### 先分配角色

在改颜色前，先写一张最小的角色表：

| 角色 | 用途 | 例子 |
| --- | --- | --- |
| canvas | 页面背景 | `--color-canvas` |
| text | 正文与标题 | `--color-text` |
| muted | 次要说明、时间、单位 | `--color-text-muted` |
| accent | 主操作、当前选中、关键数字 | `--color-accent` |
| state | 成功、警告、错误 | `--color-success` / `--color-danger` |

需要 surface 时再加一层，但不要每个区块都给一个 surface。

### 判断规则

- 同一含义只对应一种颜色；不要让“蓝色”一会儿表示链接、一会儿表示成功、一会儿只是装饰。
- 强调色应该稀缺。它标记操作或状态，不是每个标题的点缀。
- 渐变、半透明、颗粒、噪点可以保留，但要能回答：它们服务哪个材质、光线或空间概念？
- 如果渐变让正文对比度下降、让重点变模糊，或者只是“看起来高级”，删。
- 深色模式要重新分配角色，不是把亮色模式简单反相。
- 正文对比度目标 4.5:1；大字号和 UI 边界至少 3:1。最终以实际背景计算，不靠肉眼猜。

### 修复手法

1. 统计现有颜色，合并近似值。
2. 先保留中性色，再选一个 accent。
3. 把装饰性颜色删掉，或者降为低饱和背景。
4. 用 token 命名角色，不在组件里散落 hex。
5. 如果品牌色必须保留，让它承担 accent 或品牌识别，不要让所有控件都染成它。

### 例子

Bad：

```css
.hero { background: linear-gradient(135deg, #7c3aed, #06b6d4); }
.card { background: rgba(255,255,255,.12); border: 1px solid #a78bfa; }
.button { background: linear-gradient(90deg, #8b5cf6, #ec4899); }
```

Better：

```css
:root {
  --color-canvas: #f7f6f2;
  --color-text: #1d1d1b;
  --color-text-muted: #6b6a64;
  --color-accent: #1f5eff;
}
.hero { background: var(--color-canvas); }
.button { background: var(--color-accent); color: #fff; }
```

### 扫描器对应

`color.palette-sprawl`、`color.gradient-overload`、`container.glass`。扫描器数的是字面量，不能判断语义；角色表要人来定。

## Pass 4：字号与对齐

### 常见 AI 味信号

- 标题 64px、副标题 17px、卡片标题 19px、正文 13px、标签 11px、按钮 15px……每处一个尺寸。
- 用很多不同字号制造层次，而不是用字重、间距和颜色。
- 正文 12px 甚至 10px，靠“精致”牺牲可读性。
- 0.5px 线条在普通屏幕上几乎消失。
- 图标和文字基线不齐，按钮里的图标偏上或偏下。
- 所有文字都加粗，结果没有重点。
- 视频里的说明文字按网页 12px 的比例做，渲染出来看不清。

### 判断规则

- 主要字号 3–4 档；最多再加一个 caption 或 legal 尺寸。
- 字重 2–3 档足够。不要用 300、400、500、600、700、800 全集。
- 正文行高通常 1.4–1.7；标题 1.05–1.25。
- 中文正文每行约 20–36 字；英文约 45–75 字符。太宽会疲劳。
- 移动端正文不小于 16px；桌面正文不小于 14–16px。不是绝对法律，但低于这个范围要证明理由。
- 视频按最终分辨率和观看距离判断。1080p 横屏的正文型文字通常需要 28px 以上；竖屏更高。不要按浏览器 12px 的感觉做。
- 图标与文字用 flex 的 `align-items: center` 起步，再做 1px 级视觉微调；不要只靠 `vertical-align: middle` 猜。

### 修复手法

1. 列出所有字号，合并到 3–4 档。
2. 选一套比例（例如 1.25 或 1.333），但不必机械套满。
3. 标题用 `clamp()` 做流体尺寸，设好最小值和最大值。
4. 数字用 `font-variant-numeric: tabular-nums`，让列对齐。
5. 统一图标尺寸和容器高度；用同一套 `gap`。
6. 检查 200% 缩放、窄屏和长中文标题。

### 例子

```css
:root {
  --text-sm: 0.875rem;   /* 14px */
  --text-base: 1rem;     /* 16px */
  --text-lg: 1.5rem;     /* 24px */
  --text-xl: clamp(2.25rem, 4vw, 4rem);
}
```

不是所有页面都需要 4 档；但不要出现 11、13、15、17、19、21 这种连续微差。

### 扫描器对应

`type.scale-sprawl`、`type.tiny-text`、`type.weight-sprawl`。扫描器只统计 CSS 字面量，响应式 `clamp()` 需要人工判断。

## Pass 5：焦点

### 一屏一件事

对每个 viewport 或镜头问：

1. 第一眼应该看到什么？
2. 第二眼应该看到什么？
3. 哪个操作是主操作？
4. 哪些信息可以晚点出现、折叠或删掉？

如果答不出，先不要调视觉。把内容按“必须现在知道 / 稍后知道 / 不需要知道”三堆分开。

### 常见 AI 味信号

- 一屏 6 个同等大小的卡片，每个都在喊“看我”。
- 三四个主按钮并排，颜色一样重。
- 每个区块都有标题、副标题、说明、标签、图标和 CTA。
- 首屏塞满功能列表，但没有一句清楚的价值主张。
- 视频每个镜头都在换元素，没有停顿让观众读完。
- 网页把所有设置一次性铺开，没有渐进披露。

### 修复手法

- 删：与当前重点无关的区块。
- 降：把次要信息改成小字、低对比、折叠或后续镜头。
- 排：按阅读顺序重排，不按“对称好看”排。
- 聚：把同一组信息放到一起，用一个标题和一条分割线。
- 留：给重点留出空白；空白不是浪费，是层级。

### 网页与视频的差异

- 网页：允许渐进披露。次要设置放“高级设置”、tab、drawer 或详情页。
- 视频：不能点开。次要信息要么晚点出现，要么根本不放；每个镜头只承担一个叙事任务。

### 扫描器对应

`focus.competing-primary-actions`、`focus.section-density`、`focus.multiple-h1`。这些只是密度信号，最终要靠 3 秒测试。

## Pass 6：动效

先读 `motion-direction.md`。这里只给审查时的快速判断：

- 这个动作在引导视线、展示变化、推进叙事、维持连续性，还是提供反馈？
- 删掉它，信息或操作是否受损？不受损就删。
- 它是否和别的动作同时抢注意力？
- 它是否在用户阅读时移动文字？
- 它是否所有元素同一时长、同一缓动、同一延迟？
- 它是否无限循环，但没有状态变化？
- 网页是否尊重 `prefers-reduced-motion`？
- 视频静音、暂停在任意帧，是否仍然成立？

### 常见 AI 味信号

- 全站 `transition: all 0.25s ease`。
- 每个卡片 hover 都上浮 + 放大 + 发光。
- 背景渐变缓慢流动、漂浮光斑、鼠标跟随 blob。
- 标题逐字蹦出，正文也逐字蹦出。
- 所有区块滚动进入时都 fade-up。
- 视频镜头持续漂移，没有 settle。
- 动效很花，但没有一处帮助理解变化。

### 修复手法

- 先删无目的循环。
- 把统一时长拆成“反馈 / 小状态 / 入场 / 场景”四档。
- 入场用 ease-out，退场用 ease-in，反馈要快。
- 文字先 settle，再让人读；不要在阅读过程中持续位移。
- 逐字动画只在“解码/传输/逐条出现”有叙事意义时使用。
- 网页加 reduced-motion 分支；保留必要的状态反馈。

## 严重度与写法

| 严重度 | 判断 |
| --- | --- |
| 高 | 首屏信息读不懂；正文不可读；横向溢出/裁切；对比度严重不足；focus 不可见；动画引发眩晕或无法关闭；关键操作被装饰淹没。 |
| 中 | 重复文案明显；卡片/阴影/渐变压过内容；字号体系混乱；颜色语义冲突；多个主按钮竞争；动效机械或统一时长。 |
| 低 | 单个装饰性小字；轻微图标偏移；局部圆角不统一；不影响理解的细微节奏问题。 |

写法：

```text
[高] 文案 · index.html:24
证据：H1“让团队协作更高效”下方的副标题逐字复述同一句。
修复：删除副标题，把“讨论、文件、决策在一个工作区”移到 H1 下方作为唯一支持句。
```

不要写“建议优化视觉层级”这种无法执行的判断。每条至少有一个可指位置和一个可验证改法。

## 网页与视频的差异

| 维度 | 网页 | 代码动画/视频 |
| --- | --- | --- |
| 信息密度 | 可渐进披露，但首屏仍要一件事 | 每个镜头一件事，不能点开 |
| 字号 | 16px 正文起步，响应式 | 按最终分辨率和观看距离，通常更大 |
| 动效 | 反馈、状态变化、滚动引导 | 叙事、因果、镜头、图形变化 |
| 时长 | 反馈 80–200ms，入场 200–400ms | 镜头/场景 500–2000ms，留阅读停顿 |
| 可访问性 | reduced-motion、focus、对比度 | 静音理解、闪烁限制、字幕/文字可读 |
| 验证 | 多视口、交互状态 | 逐帧/关键帧、节奏、导出后观看 |

## 不要过度修正

去 AI 味不是把所有页面改成同一种“高级极简”。以下不是目标：

- 删掉所有颜色、圆角、阴影和动效。
- 把所有页面做成黑白 + 衬线大字 + 大留白。
- 为了“不像模板”而故意不对称、故意粗糙。
- 把有功能的卡片改成纯文字，牺牲可点击性。
- 把所有文案压成一句口号，丢掉必要信息。
- 用另一个流行风格替换上一个流行风格。

目标是：**内容决定形式，形式有职责，重点能被看见。**
