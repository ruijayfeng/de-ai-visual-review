# 动效与镜头指导

这份文档用于网页动效和代码动画（Canvas、SVG、GSAP、Remotion、CSS keyframes 等）。核心问题不是“够不够炫”，而是：**每个动作是否在替观众做事。**

## 一句话判断

如果删掉一个动作，信息、操作反馈或叙事理解都没有受损，它大概率不该存在。

## 动效的六种工作

保留动作前，先给它分配一个工作。一个动作只做一个主要工作。

| 工作 | 作用 | 例子 |
| --- | --- | --- |
| 引导 | 把视线带到下一个该看的地方 | 新元素从主标题方向进入；镜头推向关键数字 |
| 揭示 | 展示被遮住或需要展开的内容 | drawer、accordion、tooltip |
| 变化 | 让人看懂两个状态之间的关系 | 数字从 12 变到 48；柱状图增长；A 变成 B |
| 因果 | 说明“因为发生了什么，所以发生了什么” | 点击后卡片展开；数据流从 A 流向 B |
| 连续 | 维持空间/对象连续性，避免跳切 | 同一个图形从上一镜延续到下一镜 |
| 反馈 | 确认操作已发生 | hover、press、loading、success |

“强调”可以存在，但通常应通过对比、停顿或一次短促的 scale/opacity 完成，不需要持续循环。

## 编排：先写节拍，再写代码

把每个镜头/场景写成四段：

```text
establish  0–15%   建立空间、主体、视线落点
change    15–55%   发生一个主要变化
hold      55–80%   停住，让人读完/看懂
exit      80–100%  退场或过渡到下一镜
```

不是每个场景都要严格按比例，但必须有 **hold**。没有 hold 的动画会像一直在赶场。

### 编排规则

- 一个场景最多一个主动作 + 两个辅助动作。辅助动作不能同时抢视线。
- 文字先 settle，再让人读。不要在阅读过程中持续移动文字。
- 同一时间只让一个区域发生明显变化。其他区域可以静默或极慢。
- 分组出现时按阅读顺序 stagger，间隔 40–80ms；总延迟控制在 400ms 内。不要 10ms 一个字符机机枪扫射。
- 转场前先让观众看完；不要用更快的动画掩盖信息没读完。
- 镜头运动要有起点、终点和 settle。不要全程漂移。
- 场景结束保留最终帧至少 600–1200ms；有文字时按阅读时间加。

## 时长：至少分四档

下面是起始范围，不是法律。关键是**不要所有动作同一个时长**。

| 类型 | 范围 | 说明 |
| --- | --- | --- |
| 按压/点击反馈 | 80–140ms | 要快，像即时响应 |
| hover / 小状态 | 100–180ms | 颜色、透明度、轻微位移 |
| toggle / tooltip / popover | 120–220ms | 小而明确，不要拖 |
| 入场 / 揭示 | 200–400ms | 距离越远、面积越大，越长 |
| 退场 | 150–300ms | 通常比入场快 |
| 页面/场景转场 | 400–900ms | 需要空间连续性时更长 |
| 镜头运动 | 800–2000ms | 结束前留 settle |
| 阅读 hold | 600–1500ms + 阅读时间 | 不要用动画替观众读 |

### 阅读时间估算

- 中文：按 4–6 字/秒保守估算，再加 0.5–1s 反应时间。
- 英文：按 3–4 词/秒估算，再加 0.5–1s。
- 字幕/说明文字比标题需要更多时间；标题可以短 hold，正文不行。

例：一行 12 个中文字，至少约 2–3 秒可读时间。不要 800ms 就切走。

## 缓动

| 场景 | 建议 |
| --- | --- |
| 入场 | ease-out，快进慢停 |
| 退场 | ease-in，慢起快走 |
| 屏内移动 | ease-in-out |
| 反馈 | 短 ease-out，不要弹太久 |
| 镜头 | 温和的 ease-in-out，避免突然停止 |
| 进度/持续变化 | linear 可以接受 |

常用值：

```css
--ease-out: cubic-bezier(0.16, 1, 0.3, 1);
--ease-in-out: cubic-bezier(0.65, 0, 0.35, 1);
--ease-in: cubic-bezier(0.7, 0, 0.84, 0);
--ease-standard: cubic-bezier(0.4, 0, 0.2, 1);
```

不要默认 bounce/elastic。只有物体真的在模拟物理碰撞、掉落或弹簧时，bounce 才有理由。文字和小控件不要弹。

## 网页动效

### 必须做

- 用 `transform` 和 `opacity` 做动画，避免动画 `width`、`height`、`top`、`left` 造成 layout thrash。
- 用具体属性替代 `transition: all`。
- 给 `prefers-reduced-motion: reduce` 一个真正的分支。
- 保留 focus-visible、press、loading、success/error 反馈。
- 动画时长用 token，不在组件里散落 250ms。
- 测试窄屏、200% 缩放、键盘操作。

### 不要做

- 劫持滚动、强制平滑滚动、滚动时锁住页面。
- 无限漂浮的背景光斑、blob、粒子，除非它是核心叙事对象。
- 每个区块进入都 fade-up；重复多了会像模板。
- 文字 blur-in、逐字蹦出、持续呼吸。
- 自动播放带声音的媒体。
- 超过每秒 3 次的闪烁。

### reduced-motion 示例

```css
@media (prefers-reduced-motion: reduce) {
  .ambient,
  .float,
  .parallax {
    animation: none;
    transform: none;
  }

  .reveal {
    opacity: 1;
    transform: none;
    transition: opacity 120ms linear;
  }

  .button {
    transition: background-color 80ms linear, color 80ms linear;
  }
}
```

不要用一条 `* { animation: none !important; }` 把 loading、error、focus 等必要反馈也一起杀掉。先列出“纯装饰动作”，只关这些；必要反馈改成瞬时或短 opacity。

### 用 Web Animations API 写可读的时间线

```js
const easeOut = 'cubic-bezier(0.16, 1, 0.3, 1)';

title.animate(
  [
    { opacity: 0, transform: 'translateY(16px)' },
    { opacity: 1, transform: 'translateY(0)' }
  ],
  { duration: 420, easing: easeOut, fill: 'both' }
);

lines.forEach((line, i) => {
  line.animate(
    [
      { opacity: 0, transform: 'translateY(10px)' },
      { opacity: 1, transform: 'translateY(0)' }
    ],
    { duration: 320, delay: 120 + i * 60, easing: easeOut, fill: 'both' }
  );
});
```

注意：`delay` 的总和不要超过主动作太多；读者不应该等 UI 演完才能用。

## 代码动画与视频

### 时间线要是数据，不是散落的 setTimeout

差的写法：

```js
setTimeout(() => title(), 300);
setTimeout(() => lineOne(), 650);
setTimeout(() => lineTwo(), 900);
setTimeout(() => chart(), 1200);
```

更好的写法：

```js
const beats = [
  { at: 0,    duration: 400, run: showTitle },
  { at: 500,  duration: 500, run: showLineOne },
  { at: 1100, duration: 700, run: growChart },
  { at: 2200, duration: 1200, run: holdFinalFrame }
];
```

这样能一眼看出节拍，也方便整体调速、导出和测试。

### 帧率与确定性

- Canvas/JS 动画用 delta time，不要假设固定 60fps。
- 视频导出用固定 fps；同一输入应得到同一输出，避免无种子随机。
- 随机只用于不承载信息的纹理，并固定种子。
- 暂停在任意帧都应是一张成立的构图。

### 镜头

- 一个镜头只做一次主要运动：推、拉、摇、移、升、降，选一个。
- 镜头开始前留 300–600ms 建立；结束前留 settle。
- 不要全程缓慢漂移；观众会失去空间锚点。
- 镜头运动服务于“看哪里”，不是为了填满时间。
- 如果两个镜头之间是同一个对象，用连续变换或 match cut 保留连续性；不要无故跳切。

### 文字动画

- 默认动画整行/整块，不逐字。
- 逐字只在有叙事理由时使用：终端输出、解码、倒计时、逐条清单。
- 逐字也要按词/短语停顿，不要在标点处继续匀速。
- 代码/终端文字可以快，正文不要快。
- 动画结束后留足阅读时间；不要在文字还在动时切镜。

### 动效预算

每个场景：

- 1 个主动作（镜头、图形变化或文字揭示）。
- 最多 2 个辅助动作（背景、细节、强调）。
- 0 个无目的循环。环境运动只有在表达“持续状态”时保留，并且要极慢、低对比、可关闭。

## 常见反模式

| 反模式 | 为什么像 AI | 替代 |
| --- | --- | --- |
| 所有动作 250ms | 没有节奏判断 | 分反馈/入场/场景三档 |
| 每个卡片 hover 上浮发光 | 只因为“有交互” | 只给可点击卡片一个明确反馈 |
| 无限漂浮光斑 | 填空，不承载信息 | 删，或改成一次性的光线变化 |
| 全站滚动 fade-up | 模板化入场 | 只给首屏关键层级一次入场 |
| 标题逐字蹦出 | 默认“科技感” | 整行进入；只有终端/解码场景逐字 |
| 背景渐变流动 | 装饰性运动 | 静态渐变，或让渐变表达状态变化 |
| 鼠标跟随 blob | 炫技，干扰阅读 | 删 |
| 镜头一直漂移 | 没有 settle | 运动—停—读—再运动 |
| bounce 用在文字/按钮 | 物理隐喻错误 | ease-out |
| 所有元素同时出现 | 没有阅读顺序 | 按阅读顺序 40–80ms stagger |

## 审查清单

- [ ] 每个动作都能说出它的工作（引导/揭示/变化/因果/连续/反馈）。
- [ ] 删掉纯装饰动作后，信息仍完整。
- [ ] 至少有三档不同时长，不是全站 250ms。
- [ ] 文字在阅读时静止；转场前有 hold。
- [ ] 主动作同一时间只有一个。
- [ ] 镜头有建立、运动、settle。
- [ ] 静音看仍能理解。
- [ ] 暂停在任意帧，构图不崩。
- [ ] reduced-motion 下内容完整、反馈仍在。
- [ ] 没有无限循环的装饰动画抢注意力。
- [ ] 没有 `transition: all`。
- [ ] 没有为了“科技感”默认逐字/glitch/霓虹。
- [ ] 导出后按最终尺寸看一遍，不只看编辑器预览。

## 修复顺序

1. 删掉没有工作的动作。
2. 把剩余动作按“反馈 / 状态 / 入场 / 场景”分档。
3. 给文字和镜头加 hold。
4. 调整缓动：入场 ease-out，退场 ease-in。
5. 减少同时运动的对象。
6. 最后才考虑加细节。

先做减法，再调节奏。不要在 12 个同时漂浮的元素上微调缓动。
